# InspectFlow 演示知识库

版本：demo-v1  
核对日期：2026-11-01  
适用范围：当前 InspectFlow 的 bottle 示例模型、C++ HTTP 接口及 Dify 插件。

本目录是可版本管理的知识库原始材料，不是已经建立索引的 Dify 知识库。正文根据本地代码、配置及 README 静态核对编写；本次未运行模型，也未验证真实生产环境效果。

## 文件与导入范围

仅将 `documents/` 下的四份 Markdown 正文导入 Dify：

| 文件 | 条目范围 | 内容性质 |
| --- | --- | --- |
| 01_detection_results.md | RESULT-01～04 | 项目事实及解释边界 |
| 02_image_checklist.md | INPUT-01～03 | 接口事实、演示采集建议 |
| 03_demo_review_sop.md | SOP-REVIEW-01～04 | 演示用模拟 SOP |
| 04_capabilities_limits.md | LIMIT-01～04 | 已实现接口范围、未验证能力与报告约束 |

`README.md` 和 `SOURCES.md` 用于维护及审查，不作为业务检索正文导入，避免管理说明干扰召回。评测问题及答案也应放在正文目录之外。

## 内容性质

- **项目事实**：以 SOURCES.md 所列代码、配置及接口说明为依据，不代表已完成运行验证或生产认证。
- **演示用模拟 SOP / 演示建议**：为学习检索与报告流程而设计，不是企业规范、行业标准或真实生产处置依据。
- **项目报告约束**：对本演示报告的要求，不代表已有代码自动执行这些约束，仍须实现并测试。

每个条目重复包含编号、适用范围、版本及来源，便于被单独检索后仍保留上下文。条目编号可用于引用，不随措辞修改而改变；删除条目后不要把原编号分配给不同主题。

## 导入后检查

1. 检查每个分段是否同时保留标题、条目编号、内容性质和正文。正文用二级标题划分条目；实际分段必须在导入预览中核对。
2. 优先让一个片段表达一个完整条目，避免把限制条件与建议拆开。
3. 可测试“异常分数是不是概率”“正常结果能否直接放行”“推理耗时是否包含上传”“异常后怎么复核”。预期分别命中 RESULT-02、SOP-REVIEW-03、RESULT-03、SOP-REVIEW-02。
4. 测试“具体设备维修参数是什么”：本库没有这些参数，不能生成参数或伪造标准。
5. 引用应来自实际检索到的条目。找到一个编号并不等于正文支持所有结论，要逐条核对建议与证据。

本库不包含运行时检测结果。报告中的分数、标签、请求 ID 和耗时必须取自当次工具调用，不能从知识库示例或历史文本中获取。

## 维护要求

接口字段、模型类别、预处理、模型版本或服务行为改变时，重新核对相关条目并更新版本和日期。具体阈值、校准概率、准确率、延迟基准及生产合格标准均未纳入本库，不得自行补造。

本目录尚未替你提交 Git，也没有导入 Dify。跨仓库保存或共享时，一并保存 SOURCES.md 所指向的对应代码版本。
