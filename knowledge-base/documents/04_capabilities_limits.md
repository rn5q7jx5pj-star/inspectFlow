# 系统能力与限制

## LIMIT-01：适用类别与验证范围

条目编号：LIMIT-01  
适用范围：InspectFlow 当前 bottle 演示  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目配置事实与演示适用边界  
来源：SRC-MODEL-CONFIG、SRC-API、DEMO-DESIGN

当前参考配置采用 Patchcore，并指定 MVTecAD 的 bottle 类别。服务由启动参数加载模型文件，不会自动证明文件与参考配置对应。使用前需核对实际部署的模型。服务能够解码其他物体图片，不代表模型已对其他类别、真实产线或所有瓶类产品验证有效。本知识库没有生产部署验收、跨域泛化、漏检率或准确率的验证结果，不得据此宣称工业级可靠性或通用检测能力。

## LIMIT-02：缺陷类型、位置和原因的限制

条目编号：LIMIT-02  
适用范围：InspectFlow 当前 HTTP 检测接口及其 Dify 工具输出  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实与接口能力边界  
来源：SRC-API、SRC-ENGINE

推理引擎内部读取 anomaly_map 和 pred_mask，但当前 POST /v1/detections 成功响应只提供请求 ID、图像级分数、布尔标签和模型运行耗时，未返回热力图、掩码或区域坐标。当前接口也没有具体缺陷类别和生产原因字段。因此仅根据这个工具响应不能描述缺陷所在位置、声称看到了热力图，或确定裂纹、污染等类别。知识库中的复检说明也不能证明某次图片实际存在这些缺陷，更不能推导设备维修参数。

## LIMIT-03：模型信息、历史记录与部署限制

条目编号：LIMIT-03  
适用范围：InspectFlow 当前 C++ HTTP 服务  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实  
来源：SRC-API、SRC-ENGINE

当前服务提供健康检查、当前模型信息查询和图片检测三个路由。没有检测历史查询、自动生产处置或维修执行接口。模型版本来自 ONNX 元数据；不可用时返回 null，不能视为已知版本。服务只监听本机 127.0.0.1，当前代码没有访问鉴权。不能把本地演示描述为已经安全上线的公网服务。检测记录持久化、权限管理和完整生产监控需要另外实现与验证；请求 ID 本身不是历史数据库。

## LIMIT-04：检索依据不足时怎样生成报告

条目编号：LIMIT-04  
适用范围：InspectFlow 演示报告生成；需要在工作流中实现并测试  
文档版本：demo-v1；编写日期：2026-11-01  
内容性质：项目报告约束，不是已验证的自动防护能力  
来源：DEMO-DESIGN、SRC-API-DOC

检测事实必须来自当次成功调用；建议必须有适用文档支持。没有检索到依据、文档适用范围不符，或资料不能支持所问结论时，应写“未找到适用依据”或“现有信息不足以判断”，并保留已有的有效检测结果。不能伪造引用、标准编号、阈值、设备参数或生产处置结论。引用模拟 SOP 时必须注明其演示性质。检索到编号只是找到资料的线索，还需检查正文是否真的支持建议；本条文字不能替代工作流校验和实际评测。
