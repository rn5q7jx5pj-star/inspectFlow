# 检测结果说明

## RESULT-01：正常与异常标签如何解释

条目编号：RESULT-01  
适用范围：InspectFlow bottle 演示及当前 HTTP 检测接口  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实与接口解释  
来源：SRC-API、SRC-ENGINE、SRC-API-DOC（本地代码及接口说明）

成功检测返回 request_id、pred_score、pred_label、inference_ms。pred_label 是 JSON 布尔值：true 表示模型判定异常，false 表示模型判定正常，不是字符串或数值标签。C++ 服务直接读取 ONNX 模型的 pred_label 输出，没有在 HTTP 层重新计算判定阈值。报告应保留原始判定，可增加中文说明，但不能自行改判。模型判定正常不等于产品符合全部质量要求，模型判定异常也不等于已经确定具体缺陷类型。

## RESULT-02：异常分数不是异常概率

条目编号：RESULT-02  
适用范围：InspectFlow bottle 演示及当前 HTTP 检测接口  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实与解释边界  
来源：SRC-API-DOC、SRC-ENGINE、SRC-API

pred_score 是模型输出的图像级异常分数，不是经过概率校准的异常概率。不要乘以 100 后标为异常概率或模型置信度，也不要假设它始终位于 0～1。当前检测接口不返回阈值，不能因为看到某个示例分数就自行指定 0.5 为判定线。正常或异常以 pred_label 为准；模型版本、后处理或类别不同的分数不应未经验证直接比较。需要阈值解释或概率时，应先取得对应模型的配置与验证证据，本知识库没有这些数值。

## RESULT-03：推理耗时的统计范围

条目编号：RESULT-03  
适用范围：InspectFlow 当前 C++ HTTP 检测接口  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实  
来源：SRC-ENGINE、SRC-API-DOC

inference_ms 的单位为毫秒，统计 ONNX Runtime Session::Run 调用的时间。不包含图片上传、OpenCV 解码、C++ 预处理、响应序列化、插件网络传输、知识检索和报告生成。它不是用户从提交图片到看到报告的端到端耗时。报告应写“模型运行耗时”。若要展示整体耗时，需要在调用链外另行计时，并与模型运行耗时分别记录，不能据单次返回值宣称系统吞吐量或稳定延迟。

## RESULT-04：请求编号和模型版本如何记录

条目编号：RESULT-04  
适用范围：InspectFlow 当前 C++ HTTP 接口  
文档版本：demo-v1；核对日期：2026-11-01  
内容性质：项目事实  
来源：SRC-API、SRC-API-DOC

request_id 是当前服务进程内递增的请求标识，重启后重新计数，不是全局唯一检测记录编号。检测响应头 X-Request-ID 与响应体中的 request_id 可用于关联当次请求；长期记录还需时间及服务实例等信息。模型信息来自单独的 GET /v1/models/current 接口，不包含在当前检测成功响应中。model_version 为 null 时，应注明版本信息不可用，不能自行填成 1.0。单独查询的模型信息不能在模型切换场景下自动视为某次检测的可靠版本绑定。
